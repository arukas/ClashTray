# 服务请求与结果恢复（协议 3）

桌面与服务必须同步升级。协议 0（未声明）及旧协议 2 在业务执行前明确拒绝；不静默降级。产品版本及现有命令/错误枚举数字不变，新错误在尾部追加。旧 JSON 的可选运行绑定字段仍可反序列化，但不能绕过协议及所有权准入。

每次业务命令仅创建一个 RequestId。客户端在同一原始预算内最多执行一次 RecoveryOnly 重连，保持 ID、命令和载荷；连接失败且未开始写入属于 NotDispatched，写入开始后的取消/断线属于 DispatchedAwaitingResult。取消等待不能保证取消服务副作用。旧操作不因重连获得新的 3 秒（status）/15 秒（TUN）/30 秒（生命周期）/6 分钟（更新、回滚）预算。

服务实例拥有随机 ServiceInstanceId。请求可带 ExpectedServiceInstanceId，实例不符返回未知结果。结果表采用三份独立有界配额：GetStatus 观察最多 128 项、普通副作用最多 128 项、清理最多 16 项（合计最多 272 个 RequestId）。StopCore 仅作用于进程管理器自有子进程，使用清理配额；DisableTun 只有当前匹配的受管运行绑定/载荷才能使用清理配额，无效或过期目标不挤占它。测试可缩小各普通配额，清理上限为 min(16, 普通配额)。相同 ID 的查找及指纹检查跨配额进行。

执行中永不过期，完成后保留 2 分钟；不淘汰任何未过期副作用结果，也不扩大为无界队列。对应配额满时新请求 OperationBusy，其他配额仍可准入；重复清理的独立 ID 最多保留 16 项，同 ID 加入原任务。观察配额饱和不会阻止清理，也不会覆盖已缓存结果。相同 ID、版本、命令、载荷及预期实例加入原任务；不同指纹返回 RequestIdentityConflict。RecoveryOnly 不在指纹中，缓存缺失/过期/实例更换时只返回 RequestResultUnavailable，绝不重新执行。

已准入 StopCore/DisableTun 在原 30 秒/15 秒操作期限内等待冲突生命周期操作；等待时间不增加预算。等待清理时新的普通生命周期/TUN 启用请求保持 OperationBusy，防止持续普通请求抢占；GetStatus 不占操作锁。排队数量受保留配额限制，超时的结果也保留，不能假装核心已停止。TUN 在进入 single-flight 前检查每个请求绑定，进入操作锁后再次核对；底层共享事务继承原服务期限，等待取消不重放副作用。当前进程、监听归属和权限仍由服务独立核对。

客户端恢复成功须核对响应 ID、当前协议和 Completed。无法取得原结果时 Runtime 沿用现有服务状态、绑定、TUN 与代理恢复核对；未知结果不能直接显示成功或发起一个新 ID 的重做。结果缓存只在当前服务进程内生存，不提供跨服务崩溃的恰好一次承诺。

请求及响应 JSON 行分别限 64 Ki / 256 Ki 字符；请求空闲和响应写入各保持 5 秒上限。允许命令、受限路径、命名管道 ACL、服务独立进程/监听检查不变。桌面事实不是服务的安全证据。本地控制器仍是 127.0.0.1 与显式空 secret。

本次准入修改不增加协议字段、不提升协议 3 或改变能力协商，既有协议 3 App/Service 可兼容。测试包括丢响应后的全部副作用命令策略、隔离 ServiceRuntimeController 的并发去重、可控执行中的等待取消、过期、重启实例、指纹冲突、三配额饱和、有界 wire 和协议不兼容。固定官方 Mihomo 子进程覆盖查询及普通结果饱和后实际清理确认/进程退出、压力下等待清理及可控期限取消。真实 TUN On→Off、路由/DNS 与正式服务升级/进程退出时的断管仍须隔离 Windows 系统验收。
