## R1 — 查询级权限下的进程身份核验

- **状态：** 实现与隔离回归完成；真实桌面 App → LocalSystem 服务验收未做。
- **根因：** owner-table 在模块查询失败时回退到 `Process.SafeHandle`。按 PID 新建的 `Process` 属性可能要求 all-access；在只授予查询权限的 DACL 下，路径查询再次被拒绝，身份校验返回 false。
- **实际修复：** 新增显式 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 身份读取；同一句柄读取 `QueryFullProcessImageName` 与 `GetProcessTimes` 创建时间。启动时身份采集改用相同路径；owner PID 表命中后再次核验路径与创建时间。进程 PID、运行代际、服务实例和核心实例校验均保留，查询失败仍拒绝确认。
- **关键文件：** `src/ClashTray.Core/WindowsListenerOwnerTable.cs`、`src/ClashTray.Core/MihomoProcessManager.cs`、`tests/ClashTray.IntegrationTests/QueryLimitedProcessIdentityTests.cs`。
- **修复前失败证据：** 新增隔离 PowerShell 子进程、随机回环 TCP 监听和只含 `PROCESS_QUERY_LIMITED_INFORMATION` 的进程 DACL 回归。修复前正式运行 `dotnet test tests/ClashTray.IntegrationTests/ClashTray.IntegrationTests.csproj --configuration Release --property:Platform=x64 --no-restore --filter Name~QueryOnly`：1 项失败，失败断言为 `WindowsListenerOwnerTable.IsCurrentProcessIdentity` 返回 false；同一测试确认受限 DACL 下 `MainModule` 枚举被拒绝。
- **修复后验证：** 同一隔离回归 1 通过、0 失败、0 跳过。R1 后 Release x64 全解决方案构建通过，0 警告、0 错误。
- **人工验证：** 未执行真实非提升 App 连接 LocalSystem 服务核心的启动、重启、退出或 PID 复用验收。自动回归只证明 Windows 查询级进程 DACL 下的进程身份和监听 owner 关系。
- **未验证边界/剩余工作：** 需要在授权的专用 Windows 验收环境运行非提升桌面程序与已安装 LocalSystem 服务的跨权限流程；本地回归不等同于该服务边界验收。

## R4 — 保守识别 DNS YAML 监听语法

- **实际修复：** 受限解析器从 DNS section 的直接子项推断缩进；支持简单带引号的 root/子 mapping key；对 `<<`、anchor/alias、无法读取结构、已启用但 listen 不可确认等形式添加 warning 并置 `IsComplete=false`。原 YAML 不变，不引入通用 YAML 依赖。
- **关键文件：** `src/ClashTray.Core/MihomoListenerPlanAnalyzer.cs`、`tests/ClashTray.Core.Tests/MihomoListenerPlanAnalyzerTests.cs`、`tests/ClashTray.IntegrationTests/OfficialMihomoServiceInteropTests.cs`。

- **修复后验证：** 本轮 R3/R5 analyzer + readiness 联合测试 15 通过、0 失败、0 跳过；R4 解析行为亦包含其中。四空格 DNS 官方核心隔离服务回归在收尾强制门禁中验证，断言 `ProxyPortConflict`、错误包含 DNS、原配置不变且服务核心未运行。

## R3 — 用最终有效地址与传输语义确认监听

- **状态：** 实现、确定性测试和官方核心隔离回归完成；实际外部客户端/LAN 流量未做人工验收。

- **关键文件：** `src/ClashTray.Core/MihomoListenerPlanAnalyzer.cs`、`src/ClashTray.Core/WindowsListenerOwnerTable.cs`、`src/ClashTray.Core/ClashTrayRuntime.Lifecycle.cs`、`src/ClashTray.Service/ServiceRuntimeController.cs`、`src/ClashTray.Contracts/StateContracts.cs`、`tests/ClashTray.Core.Tests/MihomoListenerPlanAnalyzerTests.cs`、`tests/ClashTray.Core.Tests/RuntimeBindingCompatibilityTests.cs`、`tests/ClashTray.IntegrationTests/OfficialMihomoServiceInteropTests.cs`。

## R5 — 按逐监听状态和确定时序确认就绪

- **状态：** 完成。
- **根因：** 旧逻辑将期望的 TCP/UDP 组合压缩成端口布尔值。TCP 已归属、UDP 尚未出现时，“端口上已存在 listener”会把受管核心自己的 TCP 误判成 foreign UDP 冲突；检查阶段也可能让自定义监听先于主代理端点影响判断。
- **实际修复：** 新增共享 `ListenerReadinessEvaluator`，逐地址、端口、传输判定 `Missing`、`Owned`、`Foreign`、`Unknown`。按 HTTP→SOCKS→Mixed 顺序检查主代理的 TCP/UDP；主代理全 `Owned` 后才进入 DNS/custom listener。`Missing` 在既有 30 秒预算内以 100 ms 有界轮询；`Foreign` 立即拒绝；`Unknown` 在同一预算内重试，超时诊断指出 listener 与 owner 查询问题。controller 的 owner 检查继续先执行，仍限制 127.0.0.1，不放宽 controller 所有权。
- **关键文件：** `src/ClashTray.Core/ListenerReadinessEvaluator.cs`、`src/ClashTray.Core/WindowsListenerOwnerTable.cs`、`src/ClashTray.Core/ClashTrayRuntime.Lifecycle.cs`、`src/ClashTray.Service/ServiceRuntimeController.cs`、`tests/ClashTray.Core.Tests/ListenerReadinessEvaluatorTests.cs`。
- **修复前失败证据：** 无 sleep 的确定性回归使用注入观察序列，重现“Owned TCP + Missing UDP”被旧端口布尔分类判为 `ForeignOwner`；测试期望应为 `WaitingForListener`。此前假冲突判定会拒绝继续等待。
- **修复后正式验证：** 确定性测试先给 TCP `Owned`、UDP `Missing`，断言只等待 UDP；下一观察把 UDP 置 `Owned` 后，明确断言 Mixed 随后 DNS/custom 的检查顺序及最终 Ready。另断言 Foreign 与 Unknown 两种结果不混淆。联合 analyzer/readiness 15 通过、0 失败、0 跳过；正式构建与官方指定地址/wildcard 测试结果见 R3。
- **人工验证：** 未控制真实核心进程；采用确定性 owner 注入和隔离官方核心子进程，无固定 sleep 碰运气或结束用户进程。
- **未验证边界/剩余工作：** Windows IP Helper owner-table 权限异常采用有界重试后失败，真实机器持续系统级 owner 查询失败时的诊断体验仍需部署环境验收。
