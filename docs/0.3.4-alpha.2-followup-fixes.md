- 服务和本地路径从事务开始共用 linked deadline token；最终健康检查和程序设置协调不再回退到无整体期限的调用者 token，提交完成前再检查期限。

## F6：CI 调用者权限必须显式隔离

- 发布前推送 `95d7341` 的 [CI #97](https://github.com/arukas/ClashTray/actions/runs/36848777412) 构建和官方门禁通过，但 Integration 41/42 通过、1 失败。浏览器中的登录日志确认失败为 `QueryOnlyProcessDaclStillConfirmsImageCreationTimeAndListenerOwner` 第 43 行：预期 `MainModule` 抛出 Win32Exception，实际未抛出。Core/coverage 因前一步失败没有执行。这是本轮新取得的完整失败证据，不归因于此前两次历史失败。
- 旧夹具只限制自有子进程的 DACL，未限制调用者特权；带 SeDebugPrivilege 的调用者可以绕过进程 DACL。依据 [Microsoft 进程权限说明](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights) 及 [CreateRestrictedToken](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-createrestrictedtoken)，复制当前 token 并使用 DISABLE_MAX_PRIVILEGE，在 RunImpersonated 的同步作用域执行权限断言与实际身份/监听查询。
- 保留 `MainModule` 拒绝断言，增加 `SafeHandle` 拒绝断言，同时要求限权身份、TCP listener owner 成功且错误创建时间失败。没有跳过测试或降低断言；只使用测试自有子进程及复制 token，退出作用域恢复调用者，finally 清理子进程，不更改主进程 token、当前用户或机器权限。
- 修复后完整 Release x64 build 0 警告、0 错误；最终官方强制门禁 13/13、Integration 42/42 通过，均无失败或跳过。TRX：`tests/ClashTray.IntegrationTests/TestResults/alpha2-fixes/f6-official/official-mihomo-results/official-mihomo.trx`、`tests/ClashTray.IntegrationTests/TestResults/alpha2-fixes/f6-integration-required.trx`。Core 产品代码未改变，完整 593 项及新覆盖率结果仍见前节，远端 CI 将重新执行全套。
