本次 **0.3.6 正式版** 汇总代码结构优化及后续复审修补，保持现有功能范围，没有开放 P2 功能。服务协议继续使用 **3**，内置官方 Mihomo 固定为 **v1.19.31**，MetaCubeXD 固定为 **v1.273.1**。

- 统一本地与服务的核心启动就绪确认，保留进程归属、端口、控制器绑定和取消检查。
- 拆出服务请求台账与核心更新事务；生命周期、TUN 和更新继续使用统一操作锁。
- 明确设置提交、配置切换、本地启动及退出清理的事务与资源归属，保留网络恢复和回滚顺序。
- 提取展示逻辑程序集、设置草稿和窗口展示上下文，减少页面与运行时之间的隐式依赖。
- 共用控制器只读资源采集；快照读取不再隐式提交日志；托盘状态取本机设备事实。
- 按职责整理模块目录，补充架构依赖检查、故障回归及显式隔离测试组装。
- 固定 .NET SDK 和所有项目的 NuGet 依赖图。CI、发布和自包含打包使用锁定还原，官方核心、安全能力与完整发布测试拒绝失败或跳过的用例。
- 修复核心处于 `Validating` 时面板显示“已停止”的问题，中英文现在显示“验证中”/“Validating”。
- 底部版本信息过长时显示省略号，避免覆盖“退出”按钮；保留完整版本数据。
- 修复静默卸载在数据选择提示框处等待交互的问题：静默卸载默认保留配置、订阅和日志。交互式卸载继续提供保留、删除和取消选项，服务停止或代理恢复失败仍会中止卸载。
- 测试夹具批量保留 TCP/UDP 端口，避免在同一次分配中重复选择 UDP 冲突端口；补充端口分配及服务响应的失败诊断，保持原有发布断言。
- 核心停止和本地启动取消时，使用独立的清理预算恢复自有 System Proxy，保留用户启用偏好和原始取消结果，避免代理指向已停止的核心。
- 启动恢复识别已提交到磁盘的候选配置，避免核心运行新配置而设置回退到旧配置；同一订阅刷新时的内容备份恢复行为保持。
- System Proxy 写入后立即复查核心存活，并在检查前提交代理所有权版本。核心随后崩溃或启用收尾失败时，排队恢复仍能执行；恢复未完成时保留错误提示。
- 代理备份损坏、为 JSON `null` 或无法兑现时保持 `RestoreRequired` 并保留恢复文件；只有备份确实不存在时才允许直接确认关闭。
- 官方 Mihomo 集成测试统一采用回环端口保留夹具；安全测试的 PowerShell 监听子进程采用有界启动等待并补充诊断，继续执行原有 ACL、身份及监听归属断言。

建议使用 **Full 安装包**升级，以同步桌面应用和 Windows 服务。NoCET 继续提供关闭 CET 的自包含兼容变体，其 Windows 10 兼容性尚未在目标机器验收。

发布前最新代码的 [GitHub CI](https://github.com/arukas/ClashTray/actions/runs/38117201873) 已通过：Core **795/795**、完整 Integration **63/63**、官方 Mihomo **20/20**、安全能力 **6/6**，均无失败或跳过。官方核心与安全门禁属于 Integration 的子集；Core 行覆盖率 **80.85%**、分支覆盖率 **74.39%**，通过既有门禁。正式版 tag 的 Release 流水线重新执行锁定还原、Release 构建、官方核心、安全能力和完整测试门禁，然后构建 Full/NoCET 安装包并生成校验清单。

本地验证还包括完整 Release/Debug 构建及隔离 WinUI smoke。早期候选阶段的历史关联用例曾做 **10 轮、140 次**隔离回归，全部通过且没有跳过；这些结果不能证明旧失败的全部根因已经确定。各阶段和产物的适用范围见正式版验证记录。

**本次验收范围说明：**用户明确要求跳过目前没有条件开展的 Windows 10/11 实机和虚拟机验收，因此本次按其余自动化验证发布正式版。首次安装、实际升级/卸载、System Proxy/TUN 整机切换及恢复、睡眠和网络适配器变化、Explorer 重启、多显示器、高 DPI、高对比度及辅助技术场景仍未完成机器验收。隔离测试与安装包构建不记作这些场景通过，也不宣称量化性能提升。
