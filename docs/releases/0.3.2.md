# ClashTray 0.3.2

本版本是工程质量收口版，不加新产品功能：推进 `docs/0.3.2/` 专项规划中的结构化改造。Full 与 NoCET 内置 Mihomo v1.19.31；面向 Windows x64，发布工作流生成 Full、NoCET 和 Mini 三种安装器。

## 本版更新

### alpha.1

- 修复官方 Mihomo 服务边界集成测试遗漏请求协议版本的问题：`StartCore` 请求补发 `ServiceProtocol.CurrentVersion`，与 0.3.1 的"无版本请求明确拒绝"语义对齐。

### alpha.2

- 操作锁协议令牌化：ClashTrayRuntime 的 `bool operationLockHeld` 参数全部替换为 `OperationGate.Lease` 词法所有权令牌。锁的获取与释放改为 `using` 作用域，调用方持锁在类型层面可证，消除了靠人脑配对 bool 标志导致的重入/泄漏风险；TUN 与系统代理的"未持锁则自取"语义（阻塞等待 vs 忙则失败）逐字保留。

### alpha.3

- 操作门拆分为写者优先的独占/共享双车道：模式切换、节点选择、连接关闭、Provider 刷新、FakeIP/DNS 缓存清理、Geo 更新这 8 个纯 Mihomo 控制器变更迁移到共享车道，彼此可并发，不再被无关的串行锁拖住；核心生命周期、配置/订阅/端点/设置变更、系统代理、TUN、核心更新与关停清理保持独占车道，等待中的独占操作会挡住新的共享进入（写者优先），关停的 cleanup ownership 会排空活跃共享操作后再执行。控制器会话代际检查继续兜底核心中途重启的场景，冲突矩阵已写入 `docs/architecture.md`。新增 7 个门行为单元测试（共享并发、独占等共享、共享等独占、写者优先、quiescing 唤醒、cleanup 排空、idle 跟踪）。

### alpha.4

- 上帝类拆解第一步：`ClashTrayRuntime`（5411 → 4588 行）的远程端点刷新子系统整体迁出为独立的 `RemoteControllerRefreshCoordinator`——刷新生命周期、快照数据缓存、实时日志流与变更后随访刷新全部以会话代际 + 选择序号为键，构造注入 `EndpointSessionManager` 与发布/日志/设置回调，可脱离 runtime 独立构造与单测（新增 4 个单元测试）。共用逻辑同时落位：`ControllerLogStreamReceiver`（本地/远程共用的有界结构化日志 WebSocket 接收器）与 `SnapshotDataComparer`（快照列表复用比较器）。App 层公共 API 面不变。

### alpha.5

- 上帝类拆解第二步：本地日志管线从 `ClashTrayRuntime`（4588 → 4375 行）迁出为独立的 `RuntimeLogCoordinator`——有界日志缓冲、快照镜像、Mihomo 进程 stdout/stderr 摄取与服务托管核心的实时日志 WebSocket 流统一收口，构造注入 `RuntimeStateStore` 与 API/托管方式/日志级别访问器及发布回调，新增 6 个单元测试（应用/核心日志落快照、错误流级别映射、清空发布、流启停护栏、幂等停止）。顺带删除已无调用方的 REST 日志轮询残留 `TryGetLogsAsync`。App 层公共 API 面不变。

### alpha.6

- 上帝类拆解第三步：代理操作子系统从 `ClashTrayRuntime`（4433 → 4070 行）迁出为独立的 `ProxyOperationCoordinator`——模式切换与节点选择的 latest-wins 意图合并、节点/代理组测速的 single-flight、四张有界意图表（256 上限防远程端点恶意组名撑爆）整体迁移，构造注入共享操作门、状态存储、端点会话、日志与变更执行委托。控制器会话护栏同步提炼为共享的 `ControllerSessionGuard`（runtime 与协调器同一实现，杜绝两份代际校验逻辑漂移），变更执行与组测速结果落库以委托形式留在 runtime（数据刷新锁与轮询管线仍归其所有，后续切片再迁）。新增 5 个单元测试（模式 latest-wins 合并、空白参数拒绝、quiescing 快速失败、256 忙表拒绝新组）。App 层公共 API 面不变。

### alpha.7

- 上帝类拆解第四步：本地控制器数据摄取管线从 `ClashTrayRuntime`（4070 → 3783 行）迁出为独立的 `RuntimeDataRefreshCoordinator`——六个分端点读取器（代理/流量/内存/连接/规则/Provider，失败降级为最近确认快照并记录）、聚合刷新（双重绑定校验 + 条件提交 + 快照复用比较）、模式/节点变更后的随访刷新整体迁移；核心绑定三元组（生命周期纪元/进程代际/控制器代际）以 `CoreBindingEpochs` 值对象一次性捕获，绑定判定以谓词委托注入，杜绝两份判定逻辑漂移。随迁记录类型 `ProxyDataResult`/`TrafficDataResult`/`MemoryDataResult`/`ConnectionDataResult` 提升为程序集级。新增 5 个单元测试（陈旧绑定零提交零 HTTP、全量事实提交、失败降级回填、模式随访提交、已替换会话拒绝）。App 层公共 API 面不变。

### alpha.8

- 上帝类拆解第五步：远程端点目录从 `ClashTrayRuntime`（3783 → 3656 行）迁出为独立的 `EndpointCatalogCoordinator`——元数据/凭据/证书三个存储、开通与移除协调器、目录加载、目录与会话的调和、未知/禁用端点守卫整体迁移；会话管理器与传输解析器因构造期与控制器管线耦合仍归 runtime（协调器经构造注入共享）。端点选择/测试保留 runtime 薄封装负责 quiescing 检查与取消令牌链接，刷新等待仍由远程刷新协调器承担。新增 6 个单元测试（空目录仅本地、未知端点拒绝、本地只读测试拒绝、本地选择即断开、保存后目录与存储可见、禁用端点拒绝）。App 层公共 API 面不变。

### alpha.9

- UI 冒烟测试工具（本地开发用 `--ui-smoke-test=<dir>` 入口，CI 与打包流程均未引用）整体移出 Release 编译：`Program.cs` 参数解析与 marker.log 写入、`App.xaml.cs` 冒烟字段/路径注入/托盘安装跳过/冒烟运行分支全部改为 `#if DEBUG` 条件编译，`MainWindow.SmokeTest.cs` 在非 Debug 配置由 csproj 条件排除。二进制核验：Release 产物中 `CaptureSmokeTest` 方法元数据与 `--ui-smoke-test=` 字符串字面量均为零出现，Debug 产物保持原样。顺带修复 Release 配置下 `SingleInstanceCoordinator.TryAcquire` 实参恒为 false 触发的 CA1508 死代码错误（实参按配置条件化）。Debug 冒烟流程行为不变，Release 公共 API 面不变。

### alpha.10

- 收敛 CA1031 系统性豁免：`.editorconfig` 中 Core/Service 五处分组豁免（ClashTrayRuntime、SystemProxyManager、SubscriptionScheduler、ServiceRuntimeController、ServiceCommandHost）全部移除，27 处编排层 catch-all 逐一审计——均为恢复/回滚/后台循环/IPC 边界的信任边界转译器，逐方法加 `SuppressMessage` 并附具体保留理由（如启动恢复降级、回滚必须完成、轮询循环存活、命名管道边界转为有界 ServiceResponse）。同时发现并修复两处失效配置：`[src/ClashTray.App/**/*.cs]` 分组豁免因 `**/` 不匹配零级目录对 App 直属文件从未生效（实际由 csproj `NoWarn` 承担），该死配置段移除、App 的 CA1031 保留豁免统一收口到 csproj 并注明仅限 UI 事件处理器；Service 两个文件的豁免段移除后暴露出 7 处此前被掩盖的 catch-all，已一并按上述口径处理。验收达成：Core/Service 构建零 CA1031，保留项逐条有理由。

### alpha.11

- Service 结构化落盘日志：新增 `RollingFileLoggerProvider`（`Microsoft.Extensions.Logging` 提供器）——单行结构化条目落盘 `%PROGRAMDATA%\ClashTray\logs\service-yyyyMMdd-HHmmss-N.log`，单文件 1 MB 封顶、滚动序号命名、按写入时间保留最新 4 个文件，总量硬有界；所有消息经 `ErrorSanitizer` 脱敏（Authorization 头、URL 查询凭据、用户路径）后持久化；写盘失败静默丢弃，日志故障永不拖垮服务。日志目录 ACL 收紧为 Administrators/SYSTEM 完全控制 + Users 只读（`WindowsPathSecurity.ProtectServiceLogDirectory`，随 `EnsureProgramDataDirectories` 应用）。留痕面：服务启停、Windows 服务宿主生命周期、命名管道监听启停、超限/畸形/协议版本不符/请求 ID 重用/缓存饱和/未知命令/不可信核心路径八类拒绝、命令执行与失败、TUN 事务开始/成功/失败及三处恢复路径（收敛失败、恢复重启失败、重启后确认失败）——原有 4 处 `Trace.TraceWarning` 全部替换。顺带修复两处实现缺陷：`AddProvider` 注册的提供器实例不被 `LoggerFactory` 释放（文件句柄泄漏），改由 Program/测试显式持有释放；滚动重命名原先在秒内冲突时回退追加旧文件导致文件可无限增长，改为进程内单调序号 + `CreateNew`。`LoggerFactory` 注册方式与 CA1848/CA1873（日志性能规则）对低容量服务路径豁免。新增 4 个集成测试：服务事件→日志条目、总量有界、脱敏、ACL 矩阵。

### alpha.12

- Mini 前置检测版本中央化：新增 `packaging/Get-MiniPrerequisiteVersions.ps1` 作为唯一解析口——.NET 大版本经 `dotnet msbuild -getProperty:TargetFramework` 从 App 项目读出（`net10.0` → `10`），Windows App Runtime 主次版本从 `Directory.Packages.props` 的中央 `Microsoft.WindowsAppSDK` 版本解析（`2.4.0` → `2.4`）；`Build-EXE.ps1` 调用该助手并以 `/D` 传入 Inno，`ClashTray.iss` 删除 `MiniDotNetMajorVersion "10"` 与 `'2.4'` 两个字面量，改为强制 `/D` 传入（缺失即 `#error` 编译失败）。探针验证：临时将中央 WASDK 版本改为 2.5.0，助手输出跟随为 2.5（已还原）；`Build-EXE.ps1 -Variant Mini` 端到端构建成功（`ClashTray-0.3.2-win-x64-Mini.exe`，24.97 MiB）。注：本机从 Git Bash 调起构建时 PATH 中 GNU tar 会抢在 System32 bsdtar 前导致仪表盘解压失败，属预置环境差异（CI 无此问题），探针以 System32 前置规避，不属本次改动范围。

### alpha.13

- Mini 检测的用户身份口径（OTS 提权）：安装器新增 `GetActiveSessionUserSid`——通过安装器会话内 `explorer.exe` 的属主解析交互会话用户 SID（PowerShell/CIM 实现，失败回退原 `whoami` 行为），并统一收口为 `ResolveInstallUserSid`；Mini 的 Windows App Runtime 按用户注册检查与服务安装 `--user-sid`（决定服务管道 ACL 与托管核心目录授权对象）两处调用点全部切换。修复口径：标准用户以管理员凭据 OTS 提权运行安装器时，运行时检查与服务授权锚定到实际使用 ClashTray 的桌面会话用户，而非管理员账户——消除了误过（管理员装了运行时、用户没装，运行时才崩）与误杀（用户装了、管理员没装，拒绝安装），同时避免服务把核心目录授权给错误账户。内嵌解析脚本已在本机会话验证（与 `whoami /user` 输出一致）；`docs/setup.md` 新增安装器用户身份支持矩阵（标准提权 / OTS / 无交互会话三档）。Inno 编译探针通过。OTS 真实 VM 场景仍需人工验收。

### alpha.14

- 修复 CI 偶发失败（alpha.7 Release 红）：`BooleanSingleFlightReleasesAfterFailureAndCancellation` 在观察调用方取消后立即断言 `IsBusy == false`——但 `BooleanSingleFlight` 的语义是调用方取消即刻可见、操作自身拆解（`RunAsync` finally 清理 `_active`）异步随后完成，CI 高负载下清理延续可能滞后于断言。测试改为先 `WaitForIdleAsync`（其完成源恰好在 `_active` 清理后置位，确定性同步点）再断言释放状态。被测类型行为无误，属测试断言超出契约。本地连跑 15 次全绿。

## 验证

- Debug/Release x64 完整解决方案构建零警告、零错误。
- Core 单元测试（316）与 Integration 集成测试（27，含 S4 新增的落盘日志四件套：事件→条目、总量有界、脱敏、ACL 矩阵）全部通过；最终 Release 构建与测试由 GitHub 发布工作流执行。
- Mini 探针构建端到端通过（`ClashTray-0.3.2-win-x64-Mini.exe`）；Mini 前置版本解析漂移探针通过（WASDK 2.4.0→2.5.0 跟随）；OTS 会话用户解析脚本本机验证与 `whoami /user` 一致。
- Release 二进制核验：`CaptureSmokeTest` 方法元数据与 `--ui-smoke-test=` 字面量零出现。

## 已知限制与安全说明

- 真实 TUN 未在本机验证（避免修改测试机网络状态）；真实安装器安装/升级/卸载、已安装 Windows Service、System Proxy 注册表/WinINet、Explorer 重启、多显示器/DPI/高对比度与睡眠恢复建议在安全环境中手动验收。
- OTS（管理员凭据代提权）安装场景的端到端 VM 验收待人工执行；本机已验证会话用户解析逻辑与回退路径。
- Mini 变体不内置 Mihomo 核心与 .NET/Windows App SDK 运行时，可在应用内通过经过验证的核心更新流程补齐核心。
- Wi-Fi/SSID 自动切换、ARM64、历史流量分析和更多语言仍不在本版本范围内。
