# ClashTray 0.3.2

本版本是工程质量收口版，不加新产品功能：推进 `docs/0.3.2/` 专项规划中的结构化改造。Full 与 NoCET 内置 Mihomo v1.19.31；面向 Windows x64，发布工作流生成 Full、NoCET 和 Mini 三种安装器。

## 本版更新

### alpha.1

- 修复官方 Mihomo 服务边界集成测试遗漏请求协议版本的问题：`StartCore` 请求补发 `ServiceProtocol.CurrentVersion`，与 0.3.1 的"无版本请求明确拒绝"语义对齐。

### alpha.2

- 操作锁协议令牌化：ClashTrayRuntime 的 `bool operationLockHeld` 参数全部替换为 `OperationGate.Lease` 词法所有权令牌。锁的获取与释放改为 `using` 作用域，调用方持锁在类型层面可证，消除了靠人脑配对 bool 标志导致的重入/泄漏风险；TUN 与系统代理的"未持锁则自取"语义（阻塞等待 vs 忙则失败）逐字保留。

### alpha.3

- 操作门拆分为写者优先的独占/共享双车道：模式切换、节点选择、连接关闭、Provider 刷新、FakeIP/DNS 缓存清理、Geo 更新这 8 个纯 Mihomo 控制器变更迁移到共享车道，彼此可并发，不再被无关的串行锁拖住；核心生命周期、配置/订阅/端点/设置变更、系统代理、TUN、核心更新与关停清理保持独占车道，等待中的独占操作会挡住新的共享进入（写者优先），关停的 cleanup ownership 会排空活跃共享操作后再执行。控制器会话代际检查继续兜底核心中途重启的场景，冲突矩阵已写入 `docs/architecture.md`。新增 7 个门行为单元测试（共享并发、独占等共享、共享等独占、写者优先、quiescing 唤醒、cleanup 排空、idle 跟踪）。

### alpha.4

- 上帝类拆解第一步：`ClashTrayRuntime`（5411 → 4588 行）的远程端点刷新子系统整体迁出为独立的 `RemoteControllerRefreshCoordinator`——刷新生命周期、快照数据缓存、实时日志流与变更后随访刷新全部以会话代际 + 选择序号为键，构造注入 `EndpointSessionManager` 与发布/日志/设置回调，可脱离 runtime 独立构造与单测（新增 4 个单元测试）。共用逻辑同时落位：`ControllerLogStreamReceiver`（本地/远程共用的有界结构化日志 WebSocket 接收器）与 `SnapshotDataComparer`（快照列表复用比较器）。App 层公共 API 面不变。

### alpha.5

- 上帝类拆解第二步：本地日志管线从 `ClashTrayRuntime`（4588 → 4375 行）迁出为独立的 `RuntimeLogCoordinator`——有界日志缓冲、快照镜像、Mihomo 进程 stdout/stderr 摄取与服务托管核心的实时日志 WebSocket 流统一收口，构造注入 `RuntimeStateStore` 与 API/托管方式/日志级别访问器及发布回调，新增 6 个单元测试（应用/核心日志落快照、错误流级别映射、清空发布、流启停护栏、幂等停止）。顺带删除已无调用方的 REST 日志轮询残留 `TryGetLogsAsync`。App 层公共 API 面不变。

### alpha.6

- 上帝类拆解第三步：代理操作子系统从 `ClashTrayRuntime`（4433 → 4070 行）迁出为独立的 `ProxyOperationCoordinator`——模式切换与节点选择的 latest-wins 意图合并、节点/代理组测速的 single-flight、四张有界意图表（256 上限防远程端点恶意组名撑爆）整体迁移，构造注入共享操作门、状态存储、端点会话、日志与变更执行委托。控制器会话护栏同步提炼为共享的 `ControllerSessionGuard`（runtime 与协调器同一实现，杜绝两份代际校验逻辑漂移），变更执行与组测速结果落库以委托形式留在 runtime（数据刷新锁与轮询管线仍归其所有，后续切片再迁）。新增 5 个单元测试（模式 latest-wins 合并、空白参数拒绝、quiescing 快速失败、256 忙表拒绝新组）。App 层公共 API 面不变。

### alpha.7

- 上帝类拆解第四步：本地控制器数据摄取管线从 `ClashTrayRuntime`（4070 → 3783 行）迁出为独立的 `RuntimeDataRefreshCoordinator`——六个分端点读取器（代理/流量/内存/连接/规则/Provider，失败降级为最近确认快照并记录）、聚合刷新（双重绑定校验 + 条件提交 + 快照复用比较）、模式/节点变更后的随访刷新整体迁移；核心绑定三元组（生命周期纪元/进程代际/控制器代际）以 `CoreBindingEpochs` 值对象一次性捕获，绑定判定以谓词委托注入，杜绝两份判定逻辑漂移。随迁记录类型 `ProxyDataResult`/`TrafficDataResult`/`MemoryDataResult`/`ConnectionDataResult` 提升为程序集级。新增 5 个单元测试（陈旧绑定零提交零 HTTP、全量事实提交、失败降级回填、模式随访提交、已替换会话拒绝）。App 层公共 API 面不变。

## 验证

- Debug/Release x64 完整解决方案构建零警告、零错误。
- Core 单元测试与 Integration 集成测试全部通过；最终 Release 构建与测试由 GitHub 发布工作流执行。

## 已知限制与安全说明

- 真实 TUN 未在本机验证（避免修改测试机网络状态）；真实安装器安装/升级/卸载、已安装 Windows Service、System Proxy 注册表/WinINet、Explorer 重启、多显示器/DPI/高对比度与睡眠恢复建议在安全环境中手动验收。
- Mini 变体不内置 Mihomo 核心与 .NET/Windows App SDK 运行时，可在应用内通过经过验证的核心更新流程补齐核心。
- Wi-Fi/SSID 自动切换、ARM64、历史流量分析和更多语言仍不在本版本范围内。
