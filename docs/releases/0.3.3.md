# ClashTray 0.3.3

0.3.3 Alpha 系列聚焦于可靠性修复，不增加业务功能。面向 Windows x64，发布工作流生成 Full 与 NoCET 两种自包含安装器。

## 本版更新

### alpha.1

- 配置切换失败时，即使恢复日志写入失败也会继续执行资源回滚，并保留原始错误和恢复状态。
- 系统代理修改前持久化事务记录；启动恢复可处理注册表部分写入、进程中断与外部修改冲突。
- 端点删除遇到元数据保存失败时保留仍被引用的凭据和证书。
- 重复触发退出的调用方共享同一个清理完成结果；清理等待受统一时限约束，超时不会释放仍被活跃操作使用的资源。
- 端点设置表单保留 HTTPS 系统信任、自定义 CA 与 HTTP 的安全类型选择；凭据或证书更新会使旧会话失效。

### alpha.1 验证

- 完整解决方案 x64 构建通过。
- Core 单元测试 347 项通过。
- Integration 集成测试 27 项全部通过（0 失败、0 跳过），包含两项官方 Mihomo 实测；测试配置保持 TUN 禁用，未切换真实 TUN。
- 使用隔离存储、模拟注册表与模拟服务验证故障恢复路径，未切换真实 TUN。

### alpha.2

- 退出 UI 回调统一经 dispatcher 执行；补足 owner-thread、dispatcher 拒绝和异常完成的回归覆盖。
- 设置更新改为字段 patch，并在操作锁内基于最新设置合并，避免单字段动作和设置表单互相覆盖。
- 退出返回结构化清理结果；本地 Mihomo 使用受管路径校验的持久恢复记录，超时后由下一次启动按进程身份恢复。
- 连接与日志列表改用稳定行身份和增量协调，保留连接详情及日志阅读位置语义。
- 为受支持的 YAML 配置转换补充语料和边界测试，并修复语料证实的转换问题。
- 未处理异常诊断改为有界、脱敏和并发安全写入。
- 以上为可靠性与维护性整改，不增加业务功能。

### alpha.3

- 损坏或不完整的本地核心退出恢复记录返回明确失败状态，保留恢复责任，同时允许其余安全初始化继续；不因无效记录终止进程或自动启动核心。
- 受管 YAML 根字段按完整节点边界替换多行标量；无法安全转换的内容会被明确拒绝，并保留源文件和最后成功产物。
- 连接数据在进入 UI 前过滤空、缺失、重复或超长 ID；列表身份绑定 controller generation，刷新、选择和关闭操作使用正确连接身份。
- 退出准备等待、OperationGate 排空、TUN 安全点和网络清理使用分阶段预算；迟到任务继续持有依赖资源，无法确认的清理保持未知状态。

本版为可靠性整改，不增加业务功能。真实服务、System Proxy、TUN 和 WinUI 交互场景仍需在受控 Windows 环境中验收。

### alpha.8

- 停止核心流程容忍日志 WebSocket 握手超时：该超时（TimeoutException）此前未被日志流循环与停止路径捕获，异常逃逸会跳过服务停止请求与 Stopped 状态提交，核心残留运行且系统代理被撤销；现在流循环按可恢复故障重连，停止路径对历史故障免疫。
- 本地控制器会话缺失时，关闭连接、关闭全部连接、刷新 Provider、清理 FakeIP/DNS 缓存、Geo 更新等变更操作统一抛出失败，不再静默返回假成功。
- 订阅成功状态推迟到配置切换提交（NoOp/Committed）与快照刷新之后发布，不再出现先 Succeeded 后 Failed 的状态序列。
- App 与服务的本地控制器 HttpClient 统一为无限超时，请求期限由 MihomoApiClient 的每请求预算（REST 10 秒、写 15 秒）独占管理；此前 8 秒/5 秒的 HttpClient 兜底超时会以原始取消异常形态泄漏并被部分调用方当作用户取消吞掉。
- 快照变更事件在发布锁外调用：锁内仅完成快照读取、AppSnapshot 组合与委托捕获，慢订阅者不再延长其他发布者的临界区，消除锁内同步回调的设计死锁风险。
- Mihomo 子进程挂入 KILL_ON_JOB_CLOSE Job Object：宿主（App 或 Service）被强制终止时操作系统同步结束核心进程，不再只依赖下一次启动的恢复记录；Job 分配失败降级为原有行为并记录日志。
- 日志协调器 Dispose 与并发停止的取消源竞争加固：门内摘取引用、先取消后释放，停止侧容忍已释放的取消源。
- 以上为可靠性整改，不增加业务功能。
