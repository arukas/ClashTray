## alpha.3

### 更新内容

- 修复服务延迟启动后的后台恢复顺序：先接纳确认的运行绑定，再建立控制器会话，及时恢复到实际运行端点。
- 启动超时和取消保留最后监听诊断，显示实际地址、端口、TCP/UDP、Missing/Unknown/Foreign 状态及脱敏原因；继续区分内部期限与调用者取消。
- App 与 Service 共用完整运行绑定校验，拒绝只有 controller、缺少必要代理监听或记录矛盾的契约，避免错误确认核心健康。
- 旧服务缺少监听元数据时明确提示同步升级桌面程序与服务；初始化、启动对账和后台重连在创建控制器前执行相同准入校验。
- 减少每轮监听归属查询及映像路径缓冲分配。每次重试和后续检查仍重新查询，控制器写操作继续核对实时所有权。
- 修复原生 IPv6 owner 表解析遗漏接口 Scope ID，避免将不同接口的相同链路本地地址当作同一监听。

- 官方 Mihomo v1.19.31 强制门禁 **15/15** 通过，固定归档 SHA-256 一致。

## alpha.2

### 更新内容

- 修复非提升进程的 Mihomo 身份查询权限，使用同一个查询句柄核验映像路径和创建时间；查询失败继续拒绝确认。
- 统一最终 YAML 的有效监听计划、实际地址、TCP/UDP 和 wildcard dual-mode 归属；按 Missing/Owned/Foreign/Unknown 有界等待，不把自己的 TCP 监听误判成 UDP 冲突。
- System Proxy 使用已确认运行绑定的端口，并确认 Mixed TCP 覆盖实际目标 `127.0.0.1`。指定其他地址或 IPv6-only 时保持代理关闭并提示检查绑定；核心仍可健康运行。
- 支持带转义的 YAML scalar 键名，配置生成与监听分析共用解析；未识别的 root 结构不再声称分析完整，DNS TCP 冲突在启动前拒绝，保留原配置。
- 服务成功后的 `/version`、`/configs` 健康检查及设置协调继续受整体启动期限约束；保留未知派发状态的对账，避免启动第二个本地核心。
- 一次性可用端口启动只依据本次确认结果显示成功。失败保留稳定错误码和派发状态，区分忙、超时、取消、配置无效、冲突和候选耗尽，显示脱敏的具体原因。
- 修复干净 CI 中 x64 构建与 `--no-build` 门禁产物不一致的问题，统一 solution、项目测试和官方门禁的平台参数。
- 权限边界回归在禁用特权的复制 token 下执行，避免 CI runner 的调试权限绕过测试 DACL；保留高权限拒绝与限权查询成功断言。

## alpha.1

### 更新内容

- 控制器启动前按实际回环地址及 TCP/UDP 语义预检端口。自动模式会有限次数地避让冲突；固定模式会明确报告冲突，并提供单次使用可用端口的启动操作。
- 分离首选 controller 端口和确认后的实际运行绑定。服务、REST/WebSocket、TUN、仪表盘和状态快照使用相同的运行实例与地址。
- 根据 Mihomo 进程身份和 Windows 监听归属确认服务拥有当前核心；端口被另一 Mihomo 或其他进程占用时，不会把对方误认为受管核心。
- HTTP、SOCKS、Mixed 监听冲突会明确报告，不静默修改配置。Mixed 尚未就绪时不会启用 System Proxy。
- 增加启动取消、预检后竞争、重试预算、失败清理和服务未知结果调和处理；设置迁移到 schema 3，IPC 协议升至 v2。
- 设置页新增中英文自动/固定 controller 策略、实际运行地址、端口冲突说明及一次性可用端口启动选项。

### 自动化验证

- Core 492/492、Integration 37/37 通过，均无失败或跳过。
