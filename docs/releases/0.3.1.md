# ClashTray 0.3.1 alpha

本 alpha 聚焦运行时状态并发 remediation，目标是让核心生命周期、TUN/System Proxy 操作、Controller 刷新和退出清理在快速交错下仍然可收敛。它面向 Windows x64；发布工作流会生成 Full、NoCET 和 Mini 三种安装器。

## 本版更新

- Service IPC 请求增加 `RequestId`、协议版本和明确的 dispatch state；请求已经写入后发生取消、超时或断连时不再错误地回退启动第二个本地核心。Service 对已接受请求提供有界 TTL/容量的结果去重。
- Runtime snapshot 收口到单写入者 `RuntimeStateStore`，使用单调 revision 和条件提交；`Publish()` 只通知已提交状态，不再在发布线程中进行读改写。
- Core health、Controller binding、进程和代理恢复携带 lifecycle/process/controller/ownership generation，重启中间状态和旧健康响应不会关闭新一代 System Proxy 或把 Failed 改回 Running。
- 退出流程变为幂等 quiescing cleanup：先停止后台生产者并等待安全点，再通过内部 cleanup owner 处理 TUN、System Proxy、核心、会话、日志流和发布 worker；并发 Dispose 共用同一任务，清理错误会脱敏记录。
- 慢的 metrics、connections、rules、providers 和远程读取不再长期占用 local-device mutation lane；Endpoint session 连接提交采用单同步边界的 committed 判断。
- operation single-flight/latest-wins 现在区分 caller cancellation 与共享副作用生命周期；被 supersede 的 waiter 收到明确的 `Superseded`，不会错误共享后来目标的成功结果。

## 验证

- `dotnet build ClashTray.sln --configuration Debug --property:Platform=x64 --no-restore`
- Core 隔离测试：275/275 通过。
- Integration 隔离测试：22/22 通过；fixture 仅使用 fake/in-memory、TUN=false 或只读边界。
- 已确认生产代码不再存在旧的 `_snapshot = _snapshot with` 多写者赋值模式。

## 已知限制与安全说明

- 真实 TUN：未验证（用户明确禁止操作，以避免断网）。本 alpha 没有通过测试启停、切换、恢复真实 TUN，也没有修改测试机路由、DNS、网卡或 Windows Service 状态。
- 真实安装器安装/升级/卸载、已安装 Windows Service/命名管道、System Proxy 注册表/WinINet、Explorer 重启、多显示器/DPI/高对比度和睡眠恢复仍建议由用户在安全环境中手动验收。
- Wi-Fi/SSID 自动切换、ARM64、历史流量分析和更多语言仍不在本版本范围内。
