# ClashTray 0.3.1 alpha.5

本 alpha 是并发整改后的工程质量收口：修复 12 项代码审查发现的缺陷，覆盖未观察异常、状态提交缺失、协议版本兼容、TUN 状态写收口、测试确定性、资源生命周期与退出路径。Full 与 NoCET 继续内置 Mihomo v1.19.31；它面向 Windows x64，发布工作流会生成 Full、NoCET 和 Mini 三种安装器。

## 本版更新

- 修复 Mihomo 标准输出/错误读取循环只捕获取消异常的问题：进程异常退出或管道提前关闭时的 IO 异常不再成为未观察的后台任务异常，而是作为错误日志呈现。
- 后台轮询发现本地核心进程已退出时，现在会正式提交 CoreLost 事实（使控制器失效、更新状态为 Failed 并触发代理恢复复核），不再只停止日志流后静默退出循环。
- Service IPC 协议版本完全显式化：请求与响应的版本字段缺失（旧对端）时反序列化为 0 并被明确拒绝；客户端收到版本不符的响应时抛出明确的协议不兼容错误，不再被归类为"结果未知"或触发对账。
- Service 端 TUN 状态写入全部收口到同一把锁并带单调 revision；Mihomo 日志监听线程不再绕过操作门直写 TUN 状态。
- Service 控制台模式支持 Ctrl+C / 进程退出时的完整清理（TUN 关闭、代理恢复、核心停止）；Service Dispose 的 TUN 收尾改用独立 30 秒有界 cleanup token。
- Service 管道错误响应保留已解析请求的 RequestId，客户端不再把服务端执行失败误报为"响应不匹配"。
- 应用退出路径 `RequestQuitAsync` 从 `async void` 改为可等待的 `Task`，清理失败不再走 SynchronizationContext 崩溃路径，且退出动作本身保证完成。
- 修复订阅导入在默认路径下每次新建 `HttpClient` 的问题（改为带统一超时与 User-Agent 的共享客户端）；`CoreUpdater` 自持客户端现在可正确释放。
- 应用退出时退订托盘菜单、单实例激活与快照变更事件；主窗口真正关闭时退订 AppWindow Closing。
- 网络切换流水线的并发测试从墙钟 `Task.Delay` 改为虚拟时钟驱动：消抖/冷却窗口不再依赖机器速度，消除 CI 偶发失败。
- TUN 恢复路径的兜底失败（收敛、重启、重启后确认）从静默 `catch` 改为 Trace 可观测，结果载荷不变。
- 清理死代码：不可捕获的 StackOverflowException 过滤器、ServicePipeClient 不可达的取消分支。

## 验证

- Debug x64 与 Release x64 完整解决方案构建通过（0 警告、0 错误）。
- 283 项 Core 单元测试与 22 项 Integration 测试在 Debug/Release 下全部通过（含新增的服务拒绝无协议版本请求测试）；最终 Release 构建与测试仍由 GitHub 发布工作流执行。

## 已知限制与安全说明

- 真实 TUN：未验证（用户明确禁止操作，以避免断网）。本 alpha 没有通过测试启停、切换、恢复真实 TUN，也没有修改测试机路由、DNS、网卡或 Windows Service 状态。
- 真实安装器安装/升级/卸载、已安装 Windows Service/命名管道、System Proxy 注册表/WinINet、Explorer 重启、多显示器/DPI/高对比度和睡眠恢复仍建议由用户在安全环境中手动验收。
- Wi-Fi/SSID 自动切换、ARM64、历史流量分析和更多语言仍不在本版本范围内。
