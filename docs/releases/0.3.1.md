# ClashTray 0.3.1

本版本是并发整改后的工程质量收口版：在 0.3.0 基础上完成操作状态并发整改、网络配置集中化、Mihomo 核心升级，并修复并发审查与发布前排查发现的一批缺陷。Full 与 NoCET 内置 Mihomo v1.19.31；面向 Windows x64，发布工作流生成 Full、NoCET 和 Mini 三种安装器。

## 本版更新

### 并发与状态一致性

- 完成操作状态并发整改：核心生命周期、System Proxy、TUN、配置切换等操作纳入显式状态机与操作门，冲突操作序列化，崩溃与超时路径可回滚。
- 后台轮询发现本地核心进程已退出时正式提交 CoreLost 事实（使控制器失效、状态置为 Failed 并触发代理恢复复核），不再静默退出。
- Service 端 TUN 状态写入全部收口到同一把锁并带单调 revision；Mihomo 日志监听线程不再绕过操作门直写 TUN 状态。
- Service IPC 协议版本完全显式化：缺失或不符的版本字段被明确拒绝，不再被归类为"结果未知"或触发对账。
- Service 管道错误响应保留已解析请求的 RequestId，客户端不再把服务端执行失败误报为"响应不匹配"。
- 修复 Mihomo 标准输出/错误读取循环的未观察后台任务异常；TUN 恢复兜底失败从静默 catch 改为 Trace 可观测。
- 应用退出路径 `RequestQuitAsync` 从 `async void` 改为可等待的 `Task`；退出时退订托盘菜单、单实例激活、快照变更与窗口关闭事件。

### 配置与资源

- 网络配置（端口、allow-lan、IPv6、TCP 并发、日志级别等）集中到统一的设置通道。
- 修复订阅导入与核心更新路径的 `HttpClient` 泄漏：订阅导入改用带统一超时与 User-Agent 的共享客户端，`CoreUpdater` 自持客户端可正确释放。
- 网络切换流水线并发测试改为虚拟时钟驱动，消除 CI 偶发失败；清理不可捕获的异常过滤器与不可达 catch 分支。

### 安装与运行时

- Mihomo 核心升级到官方 v1.19.31（Full/NoCET 内置，SHA-256 校验）。
- Mini 变体放宽为只要求 x64 .NET Runtime 10.x（`LatestMinor`，主版本 10 内滚转）与 Windows App Runtime 2.4+，不再要求 WindowsDesktop.App。
- Mini 前置检测失败时给出官方下载地址与按用户注册说明，不再是死胡同提示；dotnet host 探测固定到 64 位 Program Files 目录。
- Service 控制台模式支持 Ctrl+C / 进程退出时的完整清理（TUN 关闭、代理恢复、核心停止）。

## 验证

- Debug/Release x64 完整解决方案构建零警告、零错误。
- 283 项 Core 单元测试与 22 项 Integration 测试在 Debug/Release 下全部通过；最终 Release 构建与测试由 GitHub 发布工作流执行。
- Mini 安装器前置检测经过 Inno 探针端到端验证：具备运行时的环境通过，缺失环境正确列出缺失项与下载地址。

## 已知限制与安全说明

- 真实 TUN 未在本机验证（避免修改测试机网络状态）；真实安装器安装/升级/卸载、已安装 Windows Service、System Proxy 注册表/WinINet、Explorer 重启、多显示器/DPI/高对比度与睡眠恢复建议在安全环境中手动验收。
- Mini 变体不内置 Mihomo 核心与 .NET/Windows App SDK 运行时，可在应用内通过经过验证的核心更新流程补齐核心。
- Wi-Fi/SSID 自动切换、ARM64、历史流量分析和更多语言仍不在本版本范围内；0.3.1 审查遗留的结构性工程项已列入 `docs/0.3.2/` 专项规划。
