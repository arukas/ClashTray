# ClashTray 0.3.4 实施结果

总体状态：S1–S4 实施完成；S5 本地与 GitHub 自动发行门禁通过，`v0.3.4-alpha.1` 已作为预发布公开发布。真实 Windows/UI 验收尚未完成，因此当前交付**尚不满足 0.3.4 正式发布条件**。

本记录仅登记本轮实际变更和验证证据。所有未在隔离环境实际验证的场景保持未验证。

## 基线与执行边界

- 起始 Git 基线为 `24f545e`（`master`）。执行开始时跟踪文件无既有修改，工作区已有的无关未跟踪文件均保留；未提交、未推送、未打 tag、未发布或改变正式产品版本。
- 环境：Windows 10.0.26300、.NET SDK 10.0.400、Windows SDK 10.0.26100、Visual Studio 18 Community。
- 固定测试核心：官方 Mihomo v1.19.31 Windows amd64。使用现有归档 SHA-256 `38b2420799d9e7cde77ec1a19c7150dd17ca77f7fb82d9f62cb8763a307eee67`；未下载或替换机器上已安装核心。
- controller 仍只绑定 `127.0.0.1`，secret 仍为空。测试使用临时目录、随机回环端口和本次测试启动的核心进程；没有安装/修改机器服务，没有更改当前真实 System Proxy 或 TUN。
- 本次实现、测试、架构说明、结果记录和 alpha 发布说明已提交；任务开始前已有的计划/提示词、审查草稿及 `.delete*` / `.releases*` 未跟踪文件均未纳入提交并保持原样。

## 切片进展

| 切片 | 状态 | 实际修改与验收证据 |
| --- | --- | --- |
| S1 端口探测与失败回归 | 完成 | 新增 `LocalPortProbe`、`ControllerPortAllocator` 和 Windows listener owner table。用独占 socket bind 逐项预检指定地址、TCP/UDP 和双栈语义；区分端口占用、拒绝访问、无效地址和未知错误。候选范围为 49152–65535，每次启动最多 16 个不同备用候选、最多 3 次进程启动尝试。新增分配/固定策略/一次性覆盖/候选耗尽/取消预检、TCP/UDP、IPv4/IPv6 与 PID 身份测试。 |
| S2 运行绑定与服务协议 | 完成 | `MihomoProcessManager` 的 Process.Start 只进入 Starting；只有当前进程代际通过实际 API 和监听归属检查后，`TryMarkReady` 才发布 Running。新增 `CoreRuntimeBinding`，包含首选与实际 controller 端口、进程路径/PID/启动时间、进程代际、服务与核心实例 ID、HTTP/SOCKS/Mixed 就绪状态和附加 listener 证据。REST、流式响应和 WebSocket 在派发前执行身份/监听 owner guard。IPC 协议升至 v2；旧协议拒绝并有回归。 |
| S3 自动避让与启动事务 | 完成 | 服务为最终配置权威：安全地在托管运行目录生成 controller 候选配置，只改 controller 到 loopback 和空 secret，不改订阅/导入源。App 服务路径与本地回退都进行端口预检，等待 /configs 与 Windows owner table 确认实际监听后才提交绑定；身份不匹配时禁止控制器请求。预检后竞争只回收本次管理的进程并按剩余候选预算重试。服务侧启动请求和就绪等待上限为 30 秒。App 启动事务从 StartCore 入口开始计时；若服务明确未派发而进入本地回退，同一 30 秒截止 token 贯穿配置读取/生成、核心验证/启动/绑定/健康确认及全部候选重试。已派发的服务请求仍通过请求 ID 与 GetStatus 调和未知结果。失败清理不复用已取消 token，进程管理器停止核心的上限为 10 秒；服务退出时另有 30 秒网络状态恢复预算。固定 controller 冲突和 HTTP/SOCKS/Mixed 冲突分别返回明确错误；固定模式的本次可用端口启动不会改写持久首选值。 |
| S4 调用链、设置与交互 | 完成 | REST/WebSocket、本地 endpoint、snapshot、TUN IPC 和仪表盘链接读取统一确认后的实际 binding；服务状态不匹配时拒绝旧绑定，服务重连/重启后按新实例重建。Mixed 未确认就绪时 System Proxy 保持关闭。设置 schema 升为 3，缺省/旧设置迁移为 AutomaticFallback，字段 patch 保留其他设置。设置页加入中英文自动/固定策略、实际地址/待确认状态、冲突解释和一次性可用端口启动操作。架构说明记录支持边界。 |
| S5 发行门禁与验收 | Alpha 自动门禁完成；真实验收未完成 | 本地 Release x64 全解方案、完整 Core/Integration、官方 v1.19.31 强制门禁和现有覆盖率门禁通过；GitHub Release 工作流也通过并创建 alpha.1。真实 WinUI 交互、服务安装/进程重启、当前 Windows 代理/TUN 和系统恢复验收未执行，故本切片及正式发行条件不标记为完成。 |

## 剩余工作与发行判定

1. 在专用 Windows 验收环境对真实 WinUI 设置流程进行人工操作验证：自动/固定策略、一次性启动、首选/实际地址和错误提示。
2. 在授权的隔离验收机验证服务安装/升级/重启、App 重开后的重连、真实 System Proxy ownership/recovery、TUN 启停失败回滚、sleep/resume 与网卡变化。
3. 完成 Full/NoCET 干净安装、0.3.3 升级和卸载恢复/保留数据场景，以及 Explorer 重启、显示器/任务栏布局、高 DPI、暗色和高对比度验收。

自动化代码门禁已通过，但上述真实系统发行验收没有证据。故**尚不满足 ClashTray 0.3.4 正式发布条件**。在明确授权的受控系统验收环境中完成这些操作并记录结果前，不应将 S5 或正式发布状态标记为完成。
