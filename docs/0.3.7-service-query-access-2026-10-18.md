# 0.3.7 服务核心身份查询修复

2026-10-18，维护者报告本机 Web 面板正常、ClashTray 托盘无法控制 Mihomo，并要求修复、提交 GitHub 和发布新版本。本次仅处理该故障及回归，不扩大产品范围。

## 本机诊断与原因

安装的 App/Service 均为 0.3.6。Windows 服务以 LocalSystem 运行，Mihomo 正常监听 127.0.0.1:19090，客户端保存的控制端口同样为 19090。只读 /version、/configs 以及服务命名管道 GetStatus 均成功。

调用已安装 ClashTray.Core 的 CaptureProcessIdentity，以当前桌面用户打开服务启动的 Mihomo 时得到 Win32 错误 5（拒绝访问）。相同身份和监听端口交给已安装 API 客户端的原有保护条件后，会抛出 ManagedCoreOwnershipException，并在 HTTP 请求发出前拒绝访问。因此 Web 正常与托盘失效可以同时发生。

现有身份校验已请求 PROCESS_QUERY_LIMITED_INFORMATION，但服务没有为安装绑定用户授予该权限。旧测试先显式授予查询权限，只验证“已有查询权限时不再请求全控制权限”，没有覆盖服务创建进程后的权限缺口。

## 实现边界

- 服务在启动、重启与回滚恢复产生的新核心完成就绪确认之前，调用进程管理器为安装绑定用户增加 0x1000 查询权限。
- 使用进程创建者持有的句柄读取及更新 DACL，不按外部 PID 重新打开写权限句柄。保留原有 ACE，仅持久化 DACL，不修改所有者或 SACL。
- 用户 SID 沿用服务安装绑定参数，不增加 IPC 参数或命令。App 继续非提升运行；PID、创建时间、路径、地址、端口与代次校验保持。
- 授权失败沿用启动清理路径，不发布 Running/ready 绑定。控制器错误显示经过清理的实际错误信息。
- 服务协议保持 3，固定 Mihomo/MetaCubeXD 版本及依赖锁文件保持。

Windows 权限定义参考 [Microsoft 进程安全和访问权限](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights)。本次不授予桌面用户终止进程、创建线程、写内存、复制句柄或修改 DACL 的权限。

## 回归证据

原始证据保存在未入库的 artifacts/fix-0.3.7/ 下，包含故障红用例、修复后测试、完整门禁与隔离 UI 截图。

- query-access：先将本测试创建的监听子进程限制为服务权限，去除调用令牌的额外权限，确认身份查询得到错误 5；再执行生产授权代码，确认身份与监听归属可以查询。检查重复授权不新增重复 ACE、SYSTEM 原有权限保留、五类危险权限仍被拒绝、错误创建时间仍被拒绝。
- service-query-red：服务接入授权前，新增官方核心用例失败；未将该失败记作通过。
- service-query-green：接入授权后，服务启动与重启的真实官方核心均可通过原有所有权保护完成版本查询和模式切换，旧进程绑定仍被拒绝。
- FailedDesktopQueryGrantStopsTheUnpublishedCore：模拟无效绑定 SID，确认实际启动过的核心退出、状态为 Stopped，且未发布运行绑定。进程是否退出使用进程枚举核对，不用“身份无法查询”替代退出证据。
- Release/Debug 全解决方案构建均通过，0 警告、0 错误。Windows 安全门禁 7/7、官方核心门禁 22/22，均无跳过。
- 隔离 WinUI smoke 退出码 0，输出 19 PNG、10 JSON；复核节点页、设置页及版本文字。使用独立目录与合成数据，不连接用户正在运行的核心。

首次完整 Integration 为 65/66：新增启动/重启用例的 Mixed TCP 端口 64805 预检报告 InUse。失败 TRX 保留在 suite-final/integration.trx；随后增加命令阶段与端口诊断，不降低断言、不跳过用例，也不更改用户网络端口。该用例随后独立重复 8 次均通过，最终完整 Release 测试在 suite-final-2/ 中通过：Integration **66/66**、Core **797/797**，均无失败、无跳过。一次端口冲突的历史原因不能由后续成功倒推。

## 升级与验证限制

升级须同步安装 App 和 Windows 服务并重启核心；旧服务已经创建的进程不会因单独替换 App 自动获得新权限。

本轮未安装、升级或卸载当前正在运行的 ClashTray，未切换其 System Proxy/TUN，未修改用户配置或订阅。新增集成测试执行真实 Windows ACL、受限令牌和官方 Mihomo，但服务控制器使用隔离路径；它不是 SCM 管理的正式 LocalSystem 服务实测。Windows 10、首次安装/真实升级卸载、真实 TUN/代理故障恢复、睡眠/网络变化、多显示器/DPI/高对比度等完整机器场景未在本轮重新验收。

发布由 v0.3.7 tag 的 GitHub Actions 重新执行门禁并生成 Full、NoCET、各自 SHA-256、SHA256SUMS.txt、release-manifest.json 和官方 Mihomo 对应源码归档。最终提交与下载工件以 GitHub Release 为准，不上传本地旧版本产物。
