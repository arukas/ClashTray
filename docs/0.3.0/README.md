# ClashTray 0.3.0 正式规划文档

> 文档状态：0.3.0 正式版范围冻结；SSID/Wi-Fi 功能明确顺延
> 目标版本：0.3.0
> 功能基线：0.2.0
> 平台范围：Windows 10 22H2 / Windows 11，x64
> 最后更新：2026-09-16

> **0.3.0 范围声明：** 本版本不包含 Wi-Fi/SSID 配置切换、SSID 读取、网络变化监听、网络规则编辑或位置权限处理。相关能力保留为后续版本设计，不属于 0.3.0 的功能、验收或发布门禁。

## 1. 文档目的

本目录把 [P2 规划草案](../p2-plan.md) 中跨度较大的候选能力收敛为一个可开发、可测试、可发布的 0.3.0 版本计划。它解决四个问题：

1. 明确 0.3.0 必须交付和明确不交付的内容。
2. 把本机运行状态与 Mihomo 控制器会话拆开，避免远程端点获得本机特权能力。
3. 明确 SSID/Wi-Fi 自动切换不进入 0.3.0，避免规划文档与发布实现混淆。
4. 给出里程碑、测试矩阵、发布门禁和停止发布条件。

这些文档是规划与设计基线。当前分支已按本基线进入实现阶段；实际完成度、验证范围和未关闭的发布门禁以代码与发布说明中的记录为准。

## 当前实现状态（2026-09-16）

当前分支已经落地并经过自动化验证的增量包括：

- Windows 网络权限为 `PermissionRequired` 时，设置页提供用户主动触发的系统设置入口，不自动弹出权限页面。
- 远程 Controller 的 loopback HTTPS/WSS transport 夹具、同源认证、系统信任/自定义 CA 校验、超时和响应大小限制。
- System Proxy 所有权快照覆盖代理地址、覆盖列表、自动配置地址和自动检测状态；外部修改时拒绝误恢复。
- 远程 Controller 部分刷新失败时保留上次确认数据和时间戳，并在主面板和页面操作中明确进入只读状态；连接恢复后操作重新启用。
- 远程端点连接状态与网络切换状态带稳定 `ErrorCode`；认证失败、证书失败、不兼容、传输失败、权限不足、网络歧义和规则目标丢失可供上层本地化。
- loopback HTTPS Controller 夹具已经覆盖 `MihomoEndpointSessionConnector + EndpointSessionManager` 的真实握手链路；远程陈旧快照会标记 `EndpointStaleResult`，恢复后清除。
- 固定的官方 Mihomo v1.19.30 已通过 PE x64、受管安装清单和 SHA-256 校验，并在 `tun.enable: false` 的最小配置下完成配置验证、启动、loopback REST `/version` 与 `/configs` 访问，以及 `/logs` WebSocket 握手。
- `ServiceRuntimeController` 已用同一份受管核心完成启动、状态确认、重启和停止的集成验证；测试探针只允许确认 TUN 已关闭，用于确保本轮不进入 TUN-enabled 路径。
- 0.3.0 已从生产运行入口移除 SSID 网络上下文源，并隐藏 SSID 规则设置卡片；不会读取 SSID、监听网络变化或处理位置权限。

这些增量仍不等于所有平台验收均已完成。当前明确未关闭的项目包括公网/局域网远程 Controller 互操作、实际 System Proxy 和 TUN 验收、已安装 Windows Service/命名管道矩阵、Full/NoCET/Mini 发行产物，以及配置切换端到端证据。配置事务证据按当前执行顺序暂缓，不应标记为已完成。SSID/Wi-Fi 自动切换不属于未验证项目，而是明确排除在 0.3.0 之外。

## 3. 0.3.0 版本结论

0.3.0 先保证 P0 本机日常路径，并纳入 P2-A 中已收口的基础远程端点能力；SSID/Wi-Fi 自动切换不在本版本范围内：

| 类型 | 纳入 0.3.0 | 说明 |
| --- | --- | --- |
| 基线修复 | 简体中文 / English 本地化闭环 | 当前 UI 仍有硬编码文本，必须先建立可维护的双语资源层 |
| 基础重构 | 本机设备状态与控制器会话分离 | 这是安全接入远程端点的前置条件 |
| 基础重构 | 本机配置切换边界 | 手动选择通过统一的验证、提交和失败保护路径 |
| 明确延期 | Wi-Fi / SSID 配置切换 | 不读取 SSID、不监听网络变化、不提供网络规则或位置权限入口；顺延后续版本 |
| P2-A | 远程 Mihomo 端点管理 | HTTPS 优先、逐端点信任、凭据保护、能力隔离 |
| 发布治理 | 单一版本源、设置迁移、集成测试与发布门禁 | 避免 0.3.0 版本字符串、数据格式和安装包产生漂移 |

以下内容不进入 0.3.0：

- 便携版或真正的无安装发行模式。
- ARM64 安装包。
- 历史流量统计与分析。
- 全局快捷键自定义。
- 简体中文和 English 之外的语言。
- 云同步、账户、遥测、自动发现远程控制器。
- 远程配置文件上传、远程核心安装、远程服务管理。
- Wi-Fi / SSID 自动切换、网络规则、SSID 读取、网络变化监听和位置权限处理。

## 4. 产品成功标准

0.3.0 可以发布的最低标准如下：

1. 0.2.0 的本机代理、System Proxy、TUN、配置、订阅、规则、连接、日志和更新路径无功能回退。
2. 所有配置切换先验证候选配置，成功后才提交活动配置；失败时恢复到最后一个已确认可用状态。
3. 0.3.0 不提供 SSID/Wi-Fi 自动切换，不读取 SSID，不扫描附近网络，不监听网络变化，不创建网络规则或位置权限流程。
4. 远程控制器永远不能触发本机 Service、核心生命周期、TUN、System Proxy、本机配置管理或本机核心更新。
5. HTTP 与 WebSocket 使用同一套认证和证书策略；不存在“REST 校验证书但 WebSocket 绕过”的分叉。
6. 端点密钥、订阅 URL 和授权头不进入日志、错误、导出、普通设置备份或崩溃文本；SSID 能力未在 0.3.0 启用。
7. 0.2.0 原有数据升级到 0.3.0 后可用；迁移失败不得破坏原文件或改变当前网络状态。
8. Full、NoCET、Mini 三种 x64 安装包使用一致的 0.3.0 版本、功能和数据格式。
9. Windows 10 22H2 与 Windows 11 x64 的规定验收矩阵通过；所有停止发布条件均已关闭。

## 5. 已确定的产品决策

| 决策编号 | 决策 | 原因 |
| --- | --- | --- |
| D-030-01 | 0.3.0 先保证 P0，并只纳入已收口的基础远程能力 | 先降低本机回归风险，再为后续能力保留边界 |
| D-030-02 | Wi-Fi / SSID 自动切换不进入 0.3.0，顺延后续版本 | 本版本不读取网络环境信息，不引入位置权限和自动切换风险 |
| D-030-03 | SSID 自动切换的启用确认、暂停和恢复交互留待后续版本重新评审 | 相关交互不是 0.3.0 的验收内容 |
| D-030-04 | SSID 规则与手动配置的优先级留待后续版本重新评审 | 0.3.0 只保证手动配置路径 |
| D-030-05 | SSID 与配置的映射模型留待后续版本重新评审 | 0.3.0 不保存或编辑 SSID 规则 |
| D-030-06 | 未来若重新纳入，只允许最小化读取并禁止扫描/BSSID/历史；0.3.0 不执行 | 为后续设计保留隐私边界，不把未来设计误当当前功能 |
| D-030-07 | 远程端点默认要求 HTTPS；HTTP 必须逐端点明确确认 | 兼容受控局域网环境，但不把明文传输变成默认值 |
| D-030-08 | 自定义 CA 只对单个端点生效，不修改 Windows 全局信任，不提供跳过证书验证 | 限制信任范围，防止静默中间人风险 |
| D-030-09 | 本机设备能力与远程控制器能力在 Core 层强制隔离 | UI 隐藏不是安全边界 |
| D-030-10 | 0.3.0 继续只发布 x64 的 Full、NoCET、Mini | ARM64 与便携版需要独立的构建和真实设备验收 |
| D-030-11 | 0.3.0 只完成简体中文与 English | 先修复资源体系，再扩展第三语言 |
| D-030-12 | 若排期必须缩减，远程端点整体顺延到 0.3.1 | 不以削弱 TLS、能力隔离、迁移或回滚换取日期 |

## 6. 术语

| 术语 | 定义 |
| --- | --- |
| 本机设备 | 当前 Windows 电脑，包括 ClashTray Service、本机 Mihomo、System Proxy、TUN 和本机数据目录 |
| 控制器会话 | 对一个 Mihomo External Controller 的 REST/WebSocket 会话，可以是本机或远程 |
| 活动目标 | 当前主面板正在查看和操作的控制器会话 |
| 活动配置 | 本机 ClashTray 当前选中的配置文件；它不等于远程 Mihomo 的配置 |
| 网络规则 | 后续版本预留的当前连接 SSID 到本机配置 ID 的用户定义映射；0.3.0 不提供 |
| 手动覆盖 | 用户在自动切换开启时手动选择本机配置，暂时压过网络规则 |
| 已确认状态 | 已从 Windows、Service 或 Mihomo API 读取并确认的实际状态，不是按钮点击后的推测值 |

## 7. 变更控制

以下变更必须先更新正式文档，再进入实现：

- 让远程目标调用任何本机特权操作。
- 允许全局跳过证书校验、把密钥放入 URL 或修改 Windows 全局根证书。
- 在后续版本重新纳入 SSID 后改变收集范围，例如加入 BSSID、附近网络扫描或历史记录。
- 将便携版、ARM64、历史统计、热键或第三语言加入 0.3.0。
- 改变数据迁移、卸载保留策略或现有 System Proxy/TUN 回滚语义。
- 为赶版本删减安全测试、升级测试或真实 Windows 验收。

普通实现细节可以在不改变外部行为和安全边界的前提下调整，但应同步更新技术设计中的组件或数据格式说明。
