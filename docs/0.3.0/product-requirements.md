# ClashTray 0.3.0 产品需求

> 状态：0.3.0 Beta 收口；SSID/Wi-Fi 功能明确顺延
> 需求版本：1.0
> 目标版本：ClashTray 0.3.0

> **Beta 范围声明：** 0.3.0 不包含 Wi-Fi/SSID 配置切换、SSID 读取、网络变化监听、网络规则编辑或位置权限处理。本文中的 NET 需求仅保留为后续版本参考，不属于 0.3.0 Beta 的实现、验收或发布门禁。

## 1. 背景

ClashTray 0.2.0 已具备 Windows x64 日常使用所需的本机 Mihomo 管理、System Proxy、TUN、订阅、代理组、规则、连接、日志和安装包路径。0.3.0 的目标不是继续横向堆叠所有 P2 功能，而是先保证本机日常路径，并安全地加入基础远程 Controller 能力。Wi-Fi/SSID 自动切换经本次范围冻结明确顺延，不在本 Beta 内实现：

1. 保证本机核心、代理、配置、订阅、System Proxy、TUN、规则、连接和日志路径不回退。
2. 在同一客户端中查看和操作用户明确添加的远程 Mihomo 控制器。

这两个场景都会改变现有“一个运行时等于一台本机核心”的假设。因此，0.3.0 同时承担三项必要的基础工作：双语资源闭环、本机状态与控制器会话分离、事务化配置切换。

## 2. 目标

### 2.1 用户目标

- 用户可以稳定地手动选择和切换本机配置；SSID 自动切换不属于 0.3.0 Beta。
- 用户可以添加、测试、选择和删除远程 Mihomo 端点。
- 用户始终能看清当前操作的是“本机”还是具体远程端点。
- 远程端点故障不能破坏本机代理、TUN、System Proxy 或本机核心状态。
- 用户可以在简体中文和 English 之间获得完整、一致、可访问的界面。

### 2.2 工程目标

- 建立本机设备状态、控制器会话状态和 UI 聚合状态的清晰边界。
- 所有本机配置切换共用一个串行、可取消、可回滚的协调器。
- HTTP 与 WebSocket 共用端点认证、TLS、超时、限流和会话代际策略。
- 新数据存储有明确版本、原子写入、损坏隔离和从 0.2.0 升级的行为。
- 建立真实 Mihomo、TLS/WebSocket 和三种安装包的验收覆盖；Windows 网络权限/SSID 监听不属于本 Beta。

## 3. 非目标

0.3.0 不提供以下能力：

- Wi-Fi/SSID 配置自动切换、SSID 读取、网络变化监听、网络规则编辑、位置权限处理或相关网络上下文状态。
- 根据 BSSID、GPS、IP 地址、网关、域名或附近网络扫描自动切换。
- 跨设备同步 SSID 规则或远程端点。
- 自动发现局域网 Mihomo 控制器。
- 远程上传、编辑或删除 Mihomo 配置文件。
- 远程启动、停止、安装、更新或替换 Mihomo 核心。
- 让远程端点控制当前 Windows 的 System Proxy、TUN 或 Service。
- 多窗口同时监控多个远程端点。
- 便携版、ARM64、历史流量、全局快捷键或第三语言。
- 修改 Windows 全局证书信任或提供“不验证证书”开关。

## 4. 用户与主要场景

### 4.1 单机用户

用户只使用本机 Mihomo。升级后原行为保持不变；远程端点不影响本机状态，SSID 自动切换不在本 Beta 中提供。

### 4.2 多网络自动切换用户（延期）

家庭/公司等网络间按 SSID 自动选择配置的场景顺延到后续版本。0.3.0 Beta 只保证用户可以手动选择配置，不读取当前 SSID，也不监听网络变化。

### 4.3 远程控制器用户

用户已经拥有自己管理的远程 Mihomo External Controller，希望在 ClashTray 中查看状态、切换模式和节点、刷新 Provider 或管理连接，但不希望远程目标影响本机网络捕获和特权服务。

## 5. 总体用户体验

### 5.1 目标选择

- 主面板提供明确的目标选择器，第一项固定为“本机”。
- 远程目标显示用户定义名称和主机，不把地址伪装成本机。
- 选中远程目标时，面板持续显示“远程”标识；HTTP 例外端点额外显示“不安全连接”标识。
- System Proxy、TUN、本机核心生命周期和本机配置区域始终属于本机设备，不随活动目标改变。
- 托盘右键菜单中的 Start、Restart、Stop、System Proxy、TUN、模式快捷项继续只作用于本机。远程操作必须进入带目标上下文的主面板。

### 5.2 状态反馈

- 开关和选择项只显示从 OS、Service 或目标控制器确认的状态。
- 正在执行的配置切换显示原因：手动选择或恢复。
- 切换失败同时说明“新配置未生效”和“已恢复到什么状态”；回滚也失败时显示高优先级错误。
- 远程端点离线时保留最后一次数据只能作为带时间戳的陈旧只读信息，不得显示为当前健康状态。

### 6.1 基线与本地化

| BAS-002 | Directory.Build.props 是产品版本的单一来源；App、安装器、文件名、发布清单和界面版本必须与发布 tag 校验一致。 |

| LOC-001 | App 的导航、按钮、菜单、对话框、错误、通知、空状态和可访问性名称必须迁移到 MRT Core 资源。 |
| LOC-002 | 0.3.0 提供完整的 zh-CN 和 en-US 资源，缺失项在构建或测试中被发现。 |
| LOC-003 | 语言选项为“跟随系统、简体中文、English”；如果运行时即时切换不能可靠完成，可明确提示重启 App 后生效，但不得重启核心。 |
| LOC-004 | 切换语言不得改变活动配置、活动目标、System Proxy、TUN、核心或端点会话。 |
| LOC-005 | 用户输入、配置内容、节点名、Provider 名和 Mihomo 原始日志不得被翻译或写回。 |
| LOC-006 | Full、NoCET、Mini 产物都必须包含同一组资源，并验证 unpackaged WinUI 3 的 PRI 加载。 |

### 6.2 事务化配置切换

| 编号 | 需求 |
| --- | --- |
| SWI-001 | 手动选择和订阅内容更新后的重新应用必须通过同一个 ConfigurationSwitchCoordinator；未来自动规则复用该边界时另行纳入版本需求。 |
| SWI-002 | 配置切换与核心启停、TUN 改变、运行端口改变、核心更新和其他重启操作共用串行操作边界。 |
| SWI-003 | 候选配置必须在改变活动配置 ID 和停止健康的旧核心之前完成静态检查及 Mihomo 验证。 |
| SWI-004 | 如果核心原本已停止，切换只更新已验证的活动配置，不得自动启动核心。 |
| SWI-005 | 如果核心原本运行，切换须保护当前期望的 System Proxy/TUN 状态，并仅在新核心健康后恢复网络捕获。 |
| SWI-006 | 成功条件至少包括服务确认运行、目标 controller 代际匹配、REST 健康检查通过和新配置身份可确认。 |
| SWI-007 | 新配置启动失败时自动恢复旧配置和原核心运行意图；恢复失败时确保 System Proxy 关闭、TUN 进入已确认安全状态，并给出可操作错误。 |
| SWI-008 | 活动配置 ID 只在事务提交点发布；UI 不得短暂显示一个最终失败的配置为已生效。 |
| SWI-009 | 事务结果必须带操作 ID、来源和会话代际；过期完成不得覆盖新会话快照。 |
| SWI-010 | 选择已经生效的配置是无副作用操作，不触发重复重启。 |

### 6.3 Wi-Fi / SSID 配置切换（延期，不属于 0.3.0 Beta）

以下 NET 编号保留为后续版本设计参考。0.3.0 Beta 不实现这些需求，不创建网络上下文源，不读取或保存 SSID，不监听网络事件，也不申请或引导位置权限；NET 不作为本 Beta 的验收或发布门禁。

| 编号 | 需求 |
| --- | --- |
| NET-001 | 自动切换默认关闭，首次启用时说明会读取当前连接 SSID 并可能重启本机 Mihomo。 |
| NET-002 | 只读取当前连接的 SSID；不得扫描附近网络，不读取或保存 BSSID，不建立连接历史。 |
| NET-003 | 每条启用规则把一个精确 SSID 映射到一个仍然存在的本机配置；多个 SSID 可以指向同一配置。 |
| NET-004 | 同一 SSID 不允许存在多个启用规则；规则编辑时直接阻止歧义，而不是在运行时猜测优先级。 |
| NET-005 | SSID 按 Windows 返回的值精确匹配，不做大小写折叠；相同 SSID 的不同物理网络在 0.3.0 无法区分，UI 必须提示这一限制。 |
| NET-006 | 用户可以配置一个可选默认配置。没有 Wi-Fi、SSID 无匹配或转到有线网络时，只有设置了默认配置才执行回退，否则保持当前配置。 |
| NET-007 | 网络事件先经过 5 秒稳定防抖；一次成功或已尝试的重启后有 30 秒冷却，同一稳定目标不重复切换。 |
| NET-008 | 事件队列采用“最新状态优先”；新网络状态可以取消尚未开始提交的旧决策，已进入本机切换临界区的事务必须安全完成或回滚。 |
| NET-009 | 用户手动选择配置后进入当前网络会话的手动覆盖；SSID 改变、系统恢复、App 重启、关闭后重新开启自动切换或用户点击“恢复自动”时重新评估规则。 |
| NET-010 | 位置权限被拒绝或不可用时进入 PermissionRequired 状态，不崩溃、不循环弹窗、不擅自打开设置；提供说明和用户触发的系统设置入口。 |
| NET-011 | 多个活动 Wi-Fi 接口无法确定主要连接时不自动切换；显示可恢复的 AmbiguousNetwork 状态。 |
| NET-012 | 睡眠恢复后等待网络稳定，再按最新状态评估；不得在适配器尚未恢复时连续重启核心。 |
| NET-013 | 规则目标配置已删除、无效或验证失败时不切换；若配置了已验证的默认配置可以回退，否则保持最后一个已确认配置。 |
| NET-014 | 自动切换关闭、权限不可用或规则存储损坏时，手动配置选择仍然可用。 |
| NET-015 | 日志默认记录规则 ID、原因和结果，不记录原始 SSID；原始 SSID 仅在规则编辑和当前网络状态 UI 中按需显示。 |

### 6.4 远程 Mihomo 端点

| 编号 | 需求 |
| --- | --- |
| REM-001 | 用户可以添加、编辑、只读测试、选择和删除最多 32 个远程端点；不提供自动发现或批量导入。 |
| REM-002 | 端点字段包括 ID、显示名称、根地址、传输安全模式、可选 secret 引用、可选自定义 CA 引用和用户确认时间。 |
| REM-003 | 地址必须是绝对 HTTP(S) URI，只允许根路径；拒绝 user-info、查询、fragment、非 HTTP(S) scheme 和嵌入凭据。 |
| REM-004 | HTTPS + Windows 系统信任是默认模式。HTTP 只在用户对该端点明确确认明文风险后允许，并持续显示警告。 |
| REM-005 | 自定义 CA 只用于被配置的 HTTPS 端点；仍须校验主机名、证书有效期、用途和完整链，不修改系统证书库，不允许接受任意证书。 |
| REM-006 | secret 使用 DPAPI CurrentUser 保护，与普通元数据分离；认证通过请求头发送，不进入 URI。 |
| REM-007 | “测试连接”只允许读取版本和必要的兼容性信息，不执行模式、节点、Provider、连接或配置改变。 |
| REM-008 | REST 与 WebSocket 必须使用同一 EndpointTransportPolicy，包括 base URI、认证、证书验证、代理禁用策略、超时和会话代际。 |
| REM-009 | 端点会话改变或重连时递增代际；旧请求、旧 WebSocket 和旧延迟测试的结果不得写入当前快照。 |
| REM-010 | 重连使用带抖动的有界退避；用户切换目标或删除端点时立即取消无用连接。 |
| REM-011 | 只有当前活动目标维持实时流；非活动端点不在后台持续拉取流量、连接和日志。 |
| REM-012 | 远程目标可按能力执行查看状态、模式切换、代理组/节点切换、延迟测试、Provider 刷新、连接关闭、缓存清理和 Geo 更新。高影响动作继续使用现有确认语义。 |
| REM-013 | 远程目标不可执行本机配置导入/删除/刷新、本机核心启停/更新、本机 Service 命令、System Proxy、TUN 或本机 Dashboard 操作。 |
| REM-014 | REM-013 的限制必须由 Core 命令策略执行；UI 隐藏控件只能作为体验层，不是唯一防线。 |
| REM-015 | 选择或断开远程端点不得改变本机活动配置、核心、System Proxy、TUN 或自动切换规则，也不得自动故障转移到另一个端点。 |
| REM-016 | 删除端点时取消会话，删除其受保护 secret 和自定义 CA 副本；删除失败必须可重试且不得把 secret 打印到错误中。 |
| REM-017 | 端点响应中的名称、日志、规则、连接、图标地址和错误均视为不可信输入，应用现有长度限制、缓冲上限、转义和脱敏规则。 |
| REM-018 | 本机目标永久存在且不可删除；远程端点存储损坏时仍可使用完整本机功能。 |

## 8. 状态模型

### 8.1 自动切换状态（后续版本预留）

以下状态仅描述后续版本可能采用的 SSID 自动切换状态机；0.3.0 Beta 不会进入这些状态，也不显示对应控制项。

| 状态 | 含义 |
| --- | --- |
| Disabled | 用户未启用自动切换 |
| WaitingForNetwork | 已启用，但当前没有稳定、可评估的网络 |
| PermissionRequired | 后续版本状态：Windows 不允许读取当前 SSID；0.3.0 Beta 不进入该状态 |
| AmbiguousNetwork | 后续版本状态：多个活动 Wi-Fi 连接且无法可靠选择；0.3.0 Beta 不进入该状态 |
| Evaluating | 正在应用防抖并计算目标 |
| Switching | 已进入配置切换事务 |
| ManualOverride | 用户选择暂时高于自动规则 |
| CoolingDown | 切换后等待网络稳定，期间只保留最新事件 |
| Failed | 最近一次评估或切换失败，但本机保持可用 |

### 8.2 控制器会话状态

| 状态 | 含义 |
| --- | --- |
| Disconnected | 没有连接，且未在重试 |
| Connecting | 正在完成版本与兼容性握手 |
| Connected | REST 健康且实时流按需连接 |
| Reconnecting | 连接丢失，按有界退避重试 |
| AuthenticationFailed | secret 缺失或不正确；等待用户修改 |
| CertificateFailed | TLS 或自定义 CA 校验失败；不得自动降级 |
| Incompatible | 端点可达但 API 不满足 0.3.0 最低能力 |
| Failed | 其他可诊断错误 |

## 9. 数据与隐私需求

- 远程端点属于当前 Windows 用户，保存在 %LOCALAPPDATA%/ClashTray；网络规则文件是后续版本预留，0.3.0 Beta 不创建或更新它。
- 后续版本若启用网络规则，SSID 才使用 DPAPI CurrentUser 保护；0.3.0 Beta 不保存 SSID。
- 远程 secret 使用独立的受保护记录；端点元数据只保存 secret 引用。
- 自定义 CA 是公钥材料，但其副本仍放在用户目录并限制为当前用户可写。
- 不上传端点、流量或使用数据，不增加遥测；0.3.0 Beta 不采集 SSID。
- 诊断日志使用稳定 ID 关联端点；SSID 规则日志和显示留待后续版本。
- 不记录 Authorization 请求头、secret、订阅 URL 查询、证书私钥或 DPAPI 明文。

## 10. 非功能需求

### 10.1 安全

- 远程能力采用显式允许列表；未知命令默认拒绝。
- 不提供证书校验绕过或 HTTPS 自动降级 HTTP。
- URI、证书、JSON、WebSocket 消息和用户可见名称均需限制大小。
- 本机 controller 继续绑定 127.0.0.1，且不因远程支持改变为空 secret 的既有本机决策。

### 10.2 可靠性

- 目标切换和核心重启都必须可取消、有超时、可重试且拒绝陈旧结果；网络变化驱动的切换留待后续版本。
- 新功能存储损坏不得阻止 App 启动、本机核心控制或网络恢复。
- 配置切换失败不得留下指向停止端口的 ClashTray-owned System Proxy。
- 睡眠恢复、适配器变化、远程断线和 App 重启不得形成重启风暴。

### 10.3 性能与资源

- 远程解析不得在 UI 线程执行高开销工作；网络事件处理留待后续版本。
- 每个活动会话沿用有界日志、连接、规则和 Provider 集合；切换目标后释放不再需要的实时流。
- 远程请求有明确超时和响应大小上限；退避最大间隔为 30 秒，并带抖动。
- UI 状态发布继续合并高频指标，不因远程流量增加无界通知。

### 10.4 可访问性与本地化

- 新增控件支持键盘导航、可见焦点、屏幕阅读器名称、高对比度和 200% DPI。
- 安全警告不能只依赖颜色。
- 中文、English 和长端点名称下不得遮挡目标身份或关键错误。

### 10.5 兼容性

- 支持 Windows 10 22H2 与 Windows 11 x64。
- 保持 Full、NoCET、Mini 三种现有发行形态。
- ARM64、x86、MSIX 和真正的便携模式不属于本版本兼容矩阵。

## 11. 核心验收场景

本节中的 Wi-Fi/SSID 场景仅作为后续版本参考，均不属于 0.3.0 Beta 验收门禁；Beta 只验收本机日常路径和纳入范围的远程 Controller 边界。

| 场景 | 期望结果 |
| --- | --- |
| 从 0.2.0 升级且没有新设置 | 本机功能与原设置保持，SSID 自动切换功能不出现，活动目标为本机 |
| 核心停止时手动选择配置 | 只提交已验证配置，核心保持停止 |
| 核心运行且 System Proxy 开启时成功切换 | 切换期间不留下死代理；新核心健康后恢复已确认的 System Proxy |
| 新配置验证失败 | 旧核心和旧活动配置不变，无网络中断 |
| 新配置启动失败但回滚成功 | 恢复旧配置与旧运行意图，向用户报告失败与已恢复结果 |
| 回滚也失败 | System Proxy 安全关闭，TUN 为已确认安全状态，显示停止发布级错误 |
| SSID 快速抖动三次（后续版本） | 不属于 0.3.0 Beta 验收；后续版本需只对最终稳定网络做一次决策 |
| 位置权限拒绝（后续版本） | 不属于 0.3.0 Beta 验收；后续版本需保持手动功能可用 |
| 相同 SSID 的不同地点（后续版本） | 不属于 0.3.0 Beta 验收；后续版本需明确提示无法区分 |
| 手动覆盖后收到相同网络事件（后续版本） | 不属于 0.3.0 Beta 验收；后续版本需保持用户选择 |
| HTTPS 证书名称错误 | REST 和 WebSocket 都拒绝连接，不能点击继续绕过 |
| 自定义 CA 正确但主机名错误 | 仍然拒绝连接 |
| HTTP 端点未确认风险 | 不保存或连接 |
| 远程端点尝试本机核心重启或 TUN | Core 策略拒绝，且没有 Service IPC 请求 |
| 远程流断开后旧响应到达 | 旧代际结果被丢弃，不覆盖当前目标 |
| 删除当前远程端点 | 会话取消、secret 清除、活动目标回到本机，本机网络不变 |
| 远程存储损坏 | 隔离损坏文件并禁用远程列表，本机功能完整可用 |
| 语言切换 | UI 文本按约定切换或提示重启 App，核心和网络状态不变 |

## 12. 发布级验收结论

只有同时满足以下条件，产品需求才算完成：

- 所有纳入 0.3.0 Beta 的 BAS、LOC、SWI、REM 需求都有实现、自动化测试或明确的真实 Windows 验收证据；NET 需求整体顺延，不作为本 Beta 的完成条件。
- 能力矩阵在 Core 层有拒绝测试。
- 配置切换成功、失败和双重失败路径均经过验证。
- HTTP 与 WebSocket 的系统信任、自定义 CA、证书错误和认证错误矩阵均经过验证。
- 0.2.0 升级、三种安装包、Windows 10/11 以及本机睡眠恢复场景通过；SSID/Wi-Fi 网络变化自动切换整体顺延，不属于本 Beta 完成条件。
- 没有未关闭的停止发布项；已知限制与非目标已写入发布说明。
